# 实时长度预检对正式检测的影响（2026-11-11）

原始 JSON 和执行脚本快照保存在本地 `scripts/loadtest/results/`（已忽略，不随仓库分发）；本报告记录测量条件、结果和局限。

本机测量：Ryzen 7 9800X3D（8 核 / 16 线程）、RTX 5070 Ti，Docker API 单 worker，数据库连接池 5＋10，AnyIO 40 个线程额度。真实鉴权、配额、检测模型、Evidence serve 和数据库落盘均启用。生成器与服务在同一台机器，未经过生产代理。

正常检测统一使用 1,469 字符、317 token、单个送检块的样本。预检使用 2,000 或 20,000 中文字符；token 数分别为 1,283 和 12,803。检测和预检使用独立 HTTP 连接池，按固定速率发射预检，独立幂等键，不自动重试。

## 修复前

原计划 2／4 并发检测 × 4 档预检 × 3 轮，每格 20 次正式检测。因第二轮出现明确故障提前中止，实际完成 10 格、200 次正式检测和 1,752 次预检，不把未完成的计划算作通过。

首轮 4 路并发检测，每行 20 个成功样本：

| 预检负载 | 检测 P50 | 检测 P95 |
| --- | ---: | ---: |
| 无预检 | 85.5 ms | 213.6 ms |
| 20 次/秒，2,000 字符 | 98.2 ms | 253.0 ms |
| 100 次/秒，2,000 字符 | 125.1 ms | 309.2 ms |
| 100 次/秒，20,000 字符 | 132.2 ms | 322.4 ms |

第二轮 4 并发＋100 次/秒、20,000 字符预检时发生连接池耗尽。该格 20 次正式检测中 17 次成功，3 次约 90.5 秒后返回 HTTP 500；699 次预检中 187 次成功，512 次约 60 秒后客户端读取超时。API 日志明确出现 QueuePool size 5 overflow 10、等待 30 秒超时。失速期间一次只读采样的 API CPU 为 0.09%、数据库 CPU 为 0%，不支持将此次故障简单归因于 GPU 算力不足。

总体 197／200 次正式检测成功、1,240／1,752 次预检成功。成功请求的 P95 单独统计，不能掩盖超时失败。成功格的检测采样窗口约 0.6～1.2 秒，属于短时干扰测量；无错误不等于持续容量达标。

所有请求结束后，仅删除本次创建的 40 个临时用户及其检测、幂等账本、配额记录，四表复查残留均为零；API 自然恢复，没有为测量重启服务。

原始证据：`preflight-interference-20261111.json`；执行脚本快照：`preflight-interference-20261111.executed.py`。JSON 不含 JWT、密码或用户原文。

## 修复与复测

预检专用鉴权回调复用原有身份与 scope 校验，在同一次同步回调内关闭数据库 Session，归还连接后才进行分词。正式检测、连接池容量、模型、额度及 token 规则未改。单连接池回归在分词入口断言没有连接被占用，并覆盖 Bearer、Cookie、游客、API key、撤销、过期、禁用和 scope 拒绝。

复测采用相同输入、运行配置和交错顺序；三轮 24 格全部完成，480／480 次正式检测、2,681／2,681 次预检成功，无 HTTP 错误、超时或失速中止。每个配置有 60 个正式检测样本。

| 检测并发 | 预检负载 | 检测 P50 | 检测 P95 |
| --- | --- | ---: | ---: |
| 2 | 无预检 | 50.9 ms | 251.0 ms |
| 2 | 20 次/秒，2,000 字符 | 52.1 ms | 230.9 ms |
| 2 | 100 次/秒，2,000 字符 | 58.4 ms | 244.5 ms |
| 2 | 100 次/秒，20,000 字符 | 69.4 ms | 286.1 ms |
| 4 | 无预检 | 96.5 ms | 282.8 ms |
| 4 | 20 次/秒，2,000 字符 | 96.4 ms | 255.4 ms |

同一次复测内，最高档相对无预检时的检测中位耗时增加约 43 ms（45%）、P95 增加约 79 ms（28%）。因此结论是：修复后本次负载没有再造成连接池耗尽，预检的 CPU、HTTP 和鉴权成本仍会在高频长文下影响正常检测速度；不能宣称零开销。低负载下 P95 偶尔更低属于短样本波动，不代表预检能加速检测。

此前失败的第二轮、4 并发＋100 次/秒、20,000 字符配置，本次 20／20 检测和 185／185 预检成功，检测 P50／P95 为 129.4／334.5 ms。修复前报告不完整，不能直接把其每档 20／40 个样本与复测 60 个样本当成严格平衡实验。

复测临时用户及对应检测、请求账本、配额记录全部清理，延后检查残留为零。实际测量约 51 秒（包含初始化、预热与清理），各格仍是短时采样，未做长时间浸泡或生产代理部署压测。前后生成器执行快照均保存；新版增加失速中止和部分结果保存，不修改业务响应或重试请求。
